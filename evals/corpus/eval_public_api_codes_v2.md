# 知识库 API 错误码

> 合成接口说明，只定义本文列出的测试错误，不包含生产系统密码或认证信息。

## 为什么使用稳定错误分类

相同的操作可能因输入、权限、数据状态或外部依赖而失败。客户端如果只显示“请求失败”，用户无法判断应该修改内容、等待完成还是联系管理员。稳定错误分类使页面能够保留必要输入，并给出与当前问题相关的下一步提示。

错误码与完整异常日志承担不同职责。面向用户的响应需要简短、可理解；内部日志通过关联编号记录诊断信息。不能为了方便前端排错而把数据库连接串或完整外部响应原样返回，也不应让错误详情暴露其他用户的文档是否存在。

## 权限不足

错误码 KB-403 表示空间或团队权限不足。遇到此类响应时，页面应检查当前所选资料范围，并允许用户移除无法使用的资料。反复点击同一个按钮不会改变权限；应通过正常成员管理或重新选择范围解决访问问题。

后端不能使用客户端缓存中的角色替代当前认证上下文。用户在另一个页面切换团队或退出登录后，原页面仍可能保留旧数据。新的请求需要重新经过访问判断，而不是因为旧页面曾经显示过某个选项就继续允许使用相关资料。

## 文档版本冲突

KB-409 表示文档版本冲突。客户端遇到 KB-409 应刷新文档版本，不得直接覆盖。冲突响应意味着保存依据与服务端当前状态不同，需要先让用户了解现有内容，再决定保留本地编辑、重新生成建议或手动整合差异。

编辑器应尽量保存用户尚未提交的本地文本，避免处理冲突时丢失工作。把旧请求自动循环发送通常不能解决版本差异，还可能掩盖真正的更新来源。人工整合完成之后，应使用新的有效版本发起保存，并单独显示实际保存结果。

## 索引服务暂不可用

IDX-503 表示索引 worker 暂时不可用。页面应区分正文已经存储与搜索暂未更新，不能让索引状态影响用户对保存结果的理解。相关后台任务可以保持可观察状态，等运行环境恢复后再通过正式入口继续处理。

运维排查需要确认工作进程、队列连接和推理配置，但这些检查不应通过浏览器传入命令完成。若请求网络结果不确定，应先查询现有任务状态，避免重复创建工作。界面上的重试操作也应关联明确任务，而不是无条件启动新任务。

## 未定义错误与客户端行为

对于文档未列出的编号，不能根据名称猜测恢复步骤。客户端可以显示通用提示和关联编号，并保留当前输入。评测问题中出现未知编号时，答案应说明材料没有提供定义，而不是拼接其他错误说明作为看似合理的处理方案。

接口回归应覆盖正常结果、已知错误和未知错误，分别检查页面提示与数据是否保持一致。仅验证响应是否能被解析不够，还需要确认失败不会误触发保存成功、发布完成或索引已更新的界面状态。
